# 03 决策记录（ADR）

> 每条记录：背景 → 决定 → 理由 → 代价 → 何时复审。
> 只追加，不删除；被推翻的决定标"已被 ADR-xxx 取代"。

## ADR-001 保留单文件架构

- 背景：Outbreak 用 55 个 IIFE 文件 + 全局命名空间，便于分目录维护。
- 决定：**我们继续单文件** `丧尸沙盒.html`。
- 理由：双击可玩、离线 PWA、单文件回滚、无构建步骤是我们的产品特性；拆文件会引入加载顺序/缓存/路径问题。
- 代价：文件大、合并冲突难、IDE 导航差。
- 缓解：用分节标题 + 速查索引；新增功能集中在对应分节，不跨节乱插。
- 复审：若单文件超过 1.2 MB 或需要多人并行开发。

## ADR-002 不采用流场寻路

- 背景：Outbreak 用"从所有人类 BFS"的双流场驱动丧尸。
- 决定：**不引入流场**，保留现有每单位 A* + 每帧预算。
- 理由：我们的地图/坐标/寻路与岗位系统已经围绕 A* 建立；流场适合"大群同目标"，不适合我们大量特殊走位与剧本控制；改动会牵动全部 AI。
- 代价：500+ 丧尸时 A* 预算可能到瓶颈。
- 缓解：先做压力测试；真到瓶颈再做"仅普通丧尸"的局部流场兜底，不替换 A*。
- 复审：压力测试单帧 >12ms 时。

## ADR-003 不采用"同种效果取最大值"

- 背景：Outbreak 的友军增益按属性取最大，防止叠加失控。
- 决定：**我们的增益继续可叠加**（光环、护盾、装备），不改成取最大。
- 理由：我们的设计目标是"越叠越强"的成长感；取最大会让多辅助阵容失去意义。
- 代价：需要更谨慎的数值上限与黑名单（如喷火/液氮不吃无限弹药）。
- 复审：出现"叠满即无敌"的具体组合时，用黑名单/软上限，不改全局规则。

## ADR-004 2.0 分阶段小批次发布

- 背景：一次大改风险高，工程可能中断。
- 决定：每个 2.x 只做一个主题 + 必要修复；每版独立公告、锚点、部署包。
- 理由：可回滚、可中断、可恢复；节点表能定位进度。
- 代价：版本号变多，文档工作量增加。
- 复审：无。

## ADR-005 重置必须基于不可变基线

- 背景：上次"恢复默认"范围不清、回不到基础值、出现极端值，最终放弃。
- 决定：
  - `BASE_UNIT` 深拷贝 + `Object.freeze`，运行期只读；
  - 重置 = 删除多余键 → 逐键写回 → `normalize` 夹值 → 存盘；
  - 提供字段/分组/兵种/全部四级范围；
  - 重置前压撤销快照。
- 理由：确定性、可测试、范围可解释。
- 代价：需要维护基线表与 normalize 表。
- 复审：若自定义兵种需要"用户基线"，再扩展"另存为基线"。

## ADR-006 地图吸附默认 1 格，可切自由

- 背景：我们的地图编辑器是自由绘画；Outbreak 只有整格落笔。
- 决定：默认 1 格吸附；可切"自由/半格"；端点/边吸附优先级高于格心；按住 Alt 临时关闭。
- 理由：新手画得整齐，老手保留自由。
- 代价：吸附冲突处理需要测试。
- 复审：玩家反馈"吸附太黏"时调整半径。

## ADR-007 实机演示必须复用真实 sim

- 背景：现有演示是假弹道，与实战不符。
- 决定：快照全局状态 → 独立演示世界 → 真实 `stepSim`/渲染 → `try/finally` 还原。
- 理由：演示与实战永远一致；不维护第二套逻辑。
- 代价：需要严格的状态隔离与性能控制。
- 复审：若演示导致主循环卡顿，改为独立 worker/离屏渲染，但仍用同一 sim。

## ADR-008 AI 装填节奏限定兵种

- 背景：每个兵种有自己的寻路/AI 节奏，新机制容易冲突。
- 决定：主动换弹/过热滞回只对步枪/机枪/狙击/盾兵/磁爆默认开启；激光/喷火/液氮保持原节奏；每兵种一个开关。
- 理由：把风险限制在"弹药型"兵种。
- 代价：不同兵种手感不完全统一。
- 复审：逐兵种验证后再扩大。

## ADR-009 版本与回滚沿用 1.x 规则

- 决定：`GAME_VERSION` + `PATCH_VERSIONS` + `历代更新.txt` + `更新公告.txt` + `回滚锚点/2.x/`。
- 理由：已有流程可靠，玩家与文档都熟悉。
- 代价：无。

## ADR-010 不做相机热点追逐

- 背景：Outbreak 的镜头会记录 2.6 秒内的命中/爆炸/枪口，按权重偏向交火处。
- 决定：**不做**。
- 理由：我们的镜头是玩家手动拖动/跟玩家，方向与"自动偏向热点"不一致；加入会抢镜、干扰操作。
- 代价：少一点"自动运镜"的观感。
- 复审：若以后做观战/回放模式，可单独加，不进主玩法。

## ADR-011 2.1 起使用四段式版本号

- 背景：2.0 后改动非常细，`2.1` / `2.1.1` 粒度不够。
- 决定：`2.<minor>.<batch>.<build><stage>`，例如 `2.1.01.1a`。
- 规则详见 `07-版本号规则.md`：可见改动 build+1；子批次验收 batch+1；阶段 a→b→rc→正式。
- 代价：版本号变长；公告与日志需要区分粒度。
- 复审：若批次过多导致难读，可合并 batch。

## ADR-012 UI 是全产品，不是一个开始界面

- 背景：Outbreak 的 UI 覆盖 16 个界面/面板：主菜单、模式卡、开局分步、HUD、暂停、结算、
  设置、存档转移、单位/地图/波次/地砖/拼接编辑器、取色板、命名框、toast/过渡。
- 决定：2.1 拆成四个子批次（2.1.01 主壳/设计系统 → 2.1.02 HUD/暂停/设置 →
  2.1.03 编辑器族 → 2.1.04 开局/引导），每批独立验收。
- 理由：一次性重做整个 UI 风险过高，且工程可能中断。
- 代价：周期长，需要持续维护 UI 地图。
- 复审：每批结束后按 06 文档更新差距矩阵。
