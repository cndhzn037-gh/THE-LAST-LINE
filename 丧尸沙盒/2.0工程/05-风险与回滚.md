# 05 风险与回滚

## 备份与回滚节奏

| 时机 | 动作 |
|---|---|
| 每个 2.x 开工前 | 复制当前主程序到 `回滚锚点/2.x-pre/`（或上一个稳定版） |
| 每个 2.x 发布 | 新建 `回滚锚点/2.x/`：主程序 + deploy.zip + SHA256 |
| 大改前（UI/地图格式/生成器） | 额外打一个 `-pre` 锚点 + 记录决策 |
| 每周 | 全目录 zip 备份到 `回滚锚点/备份/` |

## 发布门禁（每个 2.x 必须全过）

1. `node dev/selftest.mjs` 全过。
2. `node dev/newunits.mjs` 全过。
3. 本阶段新增测试全过。
4. `deploy/index.html` 与主程序哈希一致。
5. 公告/历代更新/交接文档/节点表/日志已更新。
6. 回滚锚点已建立，SHA256 已写。
7. 手机 844×390 快速走查：主界面、进入游戏、暂停、返回。

## 中断恢复流程

1. 读 `README.md` → `00-路线图.md` 确认当前阶段。
2. 打开 `01-节点总表.md`，找 `doing` 与最近的 `todo`。
3. 读 `02-工程日志.md` 最后 3 条，确认做了什么、下一步是什么。
4. 读 `03-决策记录.md`，避免推翻已定的取舍。
5. 跑一遍测试确认基线是绿的，再动手。
